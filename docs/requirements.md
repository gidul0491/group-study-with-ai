| Q16 | 자료당 최대 100,000자. |
| Q17 | 수정 없이 같은 문제로 새 차시 생성 가능. |
| 추가 | AI 응답은 JSON으로 받고 **원문 그대로 저장**한다. |
| 추가 | 협력풀이 동기화는 3초 폴링 대신 **SSE(서버가 연결을 열어 두고 밀어주는 방식)**. 개인풀이 완료 대기 화면도 같은 방식. |
| 추가 | 관리 페이지 결과 보기에서 **개인별 점수**도 본다. |

**PDF 범위**: `pdfkit` + 동봉 Noto Sans KR로 문서형 PDF를 만든다. 자료의 표·이미지·수식은 PDF에 넣지 않는다.

## 1. 개요

md·pdf 파일 또는 붙여넣은 텍스트를 읽고 AI가 문제를 출제하는 그룹 스터디용 웹사이트.
관리자는 로그인해서 시험지를 만들고, 참가자는 QR이나 링크로 들어와 로그인 없이 푼다.
모바일 화면 기준으로 설계한다.

## 2. 용어

| 용어 | 정의 |
|------|------|
| 관리자 (admin) | 서버당 1개 계정. 시험지를 만들고 결과를 본다. |
| 시험지 (exam) | 제목·자료·출제 옵션·문제를 묶은 단위. |
| 자료 (source) | 시험지에 넣은 md/pdf/텍스트 한 건. 출제의 원문. 자료마다 출제 수·유형을 정한다. |
| 문제 (question) | 자료에서 출제된 한 문항. 객관식 또는 주관식. 해설을 가진다. |
| 차시 (round) | 같은 시험지를 한 번 실시하는 단위. 시작·종료 시각, 제한시간, 응시 기록을 가진다. 1부터 순번. |
| 입장 링크 (access link) | 차시 × 모드(개인/협력)마다 1개. 토큰 URL과 QR. 열림/닫힘 상태. |
| 응시자 (participant) | 링크로 들어온 폰 하나. 입장할 때 새 한글 닉네임을 받는다. 차시 안에서만 의미 있다. |
| 개인풀이 (solo attempt) | 응시자 한 명이 한 차시를 푼 기록. |
| 협력 방 (group room) | 한 차시의 협력풀이 공간. 차시당 1개. 방장 1명, 참가자 번호. |
| 협력풀이 (group attempt) | 협력 방에서 제출한 답과 점수. 차시당 1개. |

## 3. 화면 구성

```
/                          관리자 없음 → 계정 생성 / 있음 → 로그인
/admin                     시험지 목록
/admin/new                 시험지 생성
/admin/exams/:id           시험지 상세 (문제·해설·다운로드·차시·링크·결과)
/admin/exams/:id/edit      시험지 수정
/admin/settings            공개 주소(host), 비밀번호 변경
/s/:token                  개인풀이 (링크 진입)
/g/:token                  협력풀이 (링크 진입)
```

- 관리자 화면은 로그인 세션 쿠키가 있어야 열린다. 없으면 `/`로 보낸다.
- `/s`, `/g`는 로그인 없이 토큰만으로 연다. 토큰이 없거나 닫혀 있으면 "닫힌 링크입니다" 화면.

## 4. 기능 요구사항

### 4-1 관리자 계정과 로그인

1. DB에 관리자가 없으면 `/`에서 아이디·비밀번호로 계정을 만든다. 만든 뒤에는 이 화면이 다시 나오지 않는다.
2. 로그인하면 세션 쿠키(HttpOnly, 7일)를 발급하고 `/admin`으로 간다. 로그아웃 버튼.
3. 비밀번호는 해시로만 저장한다(가이드 3-3). `/admin/settings`에서 변경.
4. 관리자는 1명이다. 추가 계정·권한은 범위 밖.

### 4-2 설정 (`/admin/settings`)

1. **공개 주소(host)**: 예 `http://192.168.0.10:3000` 또는 `https://study.example.com`. QR과 임시 링크는 이 주소로 만든다. 비어 있으면 현재 요청의 Origin을 쓴다.
2. 비밀번호 변경.

### 4-3 시험지 생성 (`/admin/new`)

1. 제목 입력.
2. 자료 목록. 항목을 자유롭게 추가·삭제·순서 변경. 항목마다:
   - 입력 방식: 파일 선택/드래그(md, pdf) 또는 텍스트 붙여넣기.
   - 주관식 문제 수, 객관식 문제 수. (둘 다 0이면 저장 불가)
   - 객관식이면 보기 개수(2~6), 최대 복수정답 수(1~보기 개수). 1이면 단일 정답.
3. 시험 옵션:
   - 공통 프롬프트 (출제 방식·중점 사항·언어 지시 등).
   - 시작 시각, 종료 시각.
   - 개인풀이 제한시간(분), 협력풀이 제한시간(분). **둘 다 필수, 1 이상.**
4. "출제" 버튼 → 서버가 자료마다 Gemini를 호출해 문제를 만든다. 진행 상황(자료 n/m)을 SSE로 보여준다.
5. 출제가 끝나면 시험지가 저장되고 **1차시**가 함께 만들어진다. 상세 화면으로 이동.
6. 주관식은 AI가 정답으로 인정할 유의어 목록을 함께 만든다. 채점은 이 목록 전부를 정답으로 본다.
7. 모든 문제는 해설을 가진다.
8. 자료는 추출한 텍스트만 저장한다. 원본 파일은 보관하지 않는다. 자료당 100,000자를 넘으면 오류.
9. PDF에서 추출한 텍스트가 비면(스캔본) 그 자료는 오류로 표시하고 저장을 막는다.

### 4-4 시험지 목록 (`/admin`)

1. 모든 시험지를 최신순으로. 제목, 문제 수, 차시 수, 최근 차시 상태(예정/진행 중/종료).
2. 클릭하면 상세로.

### 4-5 시험지 상세 (`/admin/exams/:id`)

1. 문제지. 상단 "해설 보기" 토글을 켜면 문제마다 정답·해설이 붙는다.
2. 다운로드: 문제지 md / 문제지 pdf / 답안지 md / 답안지 pdf. 답안지 = 문제 + 정답 + 해설.
3. 차시 목록. 차시마다:
   - 시작·종료 시각, 제한시간, 개인 응시 인원, 협력풀이 여부.
   - **개인풀이 링크**와 **협력풀이 링크** 각각: QR 이미지, URL 복사, 열기/닫기 토글, 재발급.
   - 닫힌 링크로 들어오면 접속할 수 없다.
   - **개인 링크를 닫으면** 풀고 있던 응시자는 그 시점에 자동 제출된다. 답하지 않은 문제는 **미선택**으로 남는다(오답 처리). 닫은 뒤의 저장 요청은 거부된다.
4. 결과 보기. 선택 순서: **차시 → 단체/개인 → 정답 표시/숨김**.
   - 단체: 협력 방 참가자 목록(번호·닉네임), 제출한 답, 점수.
   - 개인: 두 부분.
     - 응시자별 점수 표: 닉네임, 점수, 제출 시각(자동 제출 표시).
     - 문제별 통계: 정답률. 객관식이면 보기별 선택 비율, 주관식이면 제출된 답안과 비율. **미선택 비율**도 한 항목으로 함께 보인다.
   - 정답 표시를 켜면 정답 보기·정답 문구가 강조된다.
5. "새 차시 만들기": 같은 문제로 차시를 하나 더 만든다. 시작·종료·제한시간을 새로 입력. 링크도 새로 만들어진다.
6. 차시 삭제: 응시 기록과 링크가 함께 지워진다. 번호는 재부여하지 않는다.
7. 시험지 완전 삭제: 모든 차시·기록이 함께 지워진다. 확인 대화상자.

### 4-6 시험지 수정 (`/admin/exams/:id/edit`)

1. 어떤 차시에도 응시자가 없을 때만 그 자리에서 수정한다.
2. 응시자가 한 명이라도 있으면(링크로 문제지에 접속한 순간부터) 저장 시 **새 차시가 만들어지고** 그 차시부터 수정된 문제를 쓴다. 이전 차시와 기록은 그대로 남는다. 화면에 이 사실을 미리 알린다.
3. 문제는 자료별로 묶어 보인다. 할 수 있는 것:
   - 자료 통째로 삭제 / 자료 전체 재출제.
   - 문제 하나 삭제 / 문제 하나 재출제.
   - 시작·종료 시각, 제한시간 수정.
4. 재출제는 같은 자료·같은 옵션·같은 공통 프롬프트로 AI를 다시 부르며, 남아 있는 다른 문제와 겹치지 않게 지시한다.

### 4-7 개인풀이 (`/s/:token`)

1. 토큰 확인 → 열려 있고, 시험 기간 안이고, 협력풀이가 시작되지 않았으면 입장.
2. 입장 시 응시자를 만들고 한글 닉네임을 준다. 폰마다, 입장마다 새로. 닉네임은 화면 상단에 항상 보인다. 응시자 id는 쿠키에 담아 새로고침해도 같은 응시로 이어진다(쿠키 유효기간 = 차시 종료까지).
3. 입장 = 응시 시작. 이 순간부터 그 시험지는 제자리 수정이 막힌다.
4. 제한시간 카운트다운. 종료 시각·제한시간·링크 닫힘 중 먼저 오는 쪽에 자동 제출. 판정은 서버 시각 기준이며 페이지를 닫아도 서버가 시작 시각으로 처리한다. 자동 제출 시 답하지 않은 문제는 미선택(오답)이다.
5. 입력 방식:
   - 객관식 단일 정답: 라디오.
   - 객관식 복수 정답: 체크박스. 최대 복수정답 수를 넘으면 더 고를 수 없다.
   - 주관식: 한 줄 텍스트.
6. 답은 문제마다 서버에 즉시 저장한다.
7. 제출하면 서버가 채점하고 점수·문제별 정오·정답·해설을 바로 보여준다.
8. 채점 규칙:
   - 객관식: 선택 집합이 정답 집합과 완전히 같아야 정답.
   - 주관식: 제출 답과 정답·유의어를 각각 정규화(모든 공백 제거, 문장부호·특수문자 제거, 소문자, 유니코드 NFC)해 하나라도 같으면 정답.
   - 점수 = 정답 수 / 문제 수 × 100, 소수 첫째 자리.

### 4-8 협력풀이 (`/g/:token`)

1. 토큰 확인 → 열려 있고 시험 기간 안이면 방에 들어간다. 입장 시 닉네임과 **참가자 번호**(입장 순서 1, 2, 3…)를 받는다.
2. 풀이 시작 조건: **그 차시의 개인 응시자 전원이 제출(자동 제출 포함)** 했거나 개인 응시자가 0명. 조건이 안 되면 대기 화면("개인풀이 n명 중 m명 완료")을 보여주고 SSE로 갱신된다.
3. **방장**: 방에 처음 들어온 참가자. 방장만 답을 입력하고 제출할 수 있다. 다른 참가자는 같은 답안 상태를 실시간으로 본다.
4. 방장 넘겨주기: 방장이 참가자 목록에서 다른 번호를 골라 넘긴다. 방장이 연결을 끊고 30초 안에 돌아오지 않으면 남은 참가자 중 번호가 가장 빠른 사람이 방장이 된다.
5. 방장이 "시작"을 누르면 협력풀이가 시작된다. 이때부터 협력 제한시간이 흐르고, 개인풀이 신규 입장은 막힌다. 차시당 협력풀이는 1회.
6. 풀이 방식·결과는 개인풀이와 같다. 차이점: 문제마다 개인풀이 결과를 함께 보여준다.
   - 객관식: 보기별 선택 비율과 미선택 비율.
   - 주관식: 제출된 답안과 각 비율, 미선택 비율.
   - 정답은 제출 전까지 보이지 않는다.
7. 제출 후 결과 화면은 모든 참가자에게 같이 보인다.

### 4-9 공통

1. UI 언어는 한국어.
2. 시각은 서버에 UTC ISO 문자열로 저장하고, 화면에서 `Asia/Seoul`로 보여준다.
3. 시험 기간·제출 여부·잠금 판정은 전부 서버 시각으로 한다.
4. 실시간 갱신(협력 방 상태, 대기 화면, 출제 진행)은 SSE로 한다. 연결이 끊기면 브라우저가 자동 재접속한다.

## 5. AI 출제 규격

1. 제공자: Google Gemini. SDK `@google/genai`. 키는 `.env.txt`의 `GEMINI_API_KEY`, 모델은 `GEMINI_MODEL`(기본값은 구현 시 최신 안정 모델로 정하고 이 문서에 기록).
2. 자료 1건 = API 호출 1회. 요청에 담는 것: 자료 텍스트, 공통 프롬프트, 주관식/객관식 수, 보기 수, 최대 복수정답 수, 출제 언어(한국어), (재출제 시) 피해야 할 기존 문제 목록.
3. 응답은 `responseMimeType: application/json` + `responseSchema`로 JSON을 강제한다.

```json
{
  "questions": [
    {
      "type": "multiple",
      "text": "문제 본문",
      "choices": ["보기1", "보기2", "보기3", "보기4"],
      "answerIndexes": [0, 2],
      "explanation": "해설"
    },
    {
      "type": "short",
      "text": "문제 본문",
      "answers": ["정답", "유의어1", "유의어2"],
      "explanation": "해설"
    }
  ]
}
```

4. 응답 원문 JSON은 `generation_log`에 그대로 저장한다(모델명, 요청 요약, 응답, 소요 시간, 오류).
5. 검증: 문제 수·보기 수·정답 수가 옵션과 맞는지 서버가 확인한다. 어긋나면 1회 재시도, 그래도 실패하면 그 자료를 오류로 표시하고 나머지는 저장한다.
6. 호출은 자료 순서대로 직렬 실행한다(요율 제한 대비).

## 7. 데이터 모델

가이드 2장을 따른다. 시각은 `*_at` UTC ISO 문자열, 삭제는 실제 삭제(소프트 삭제 없음).

```
admin           id, username, password_hash, created_at
setting         key, value                                   -- public_base_url 등
exam            id, title, common_prompt, created_at, updated_at
source          id, round_id, seq, kind(MD|PDF|TEXT), file_name, content,
                short_count, multiple_count, choice_count, max_answer_count
round           id, exam_id, round_no, starts_at, ends_at,
                solo_limit_min, group_limit_min, created_at
access_link     id, round_id, mode(solo|group), token, is_open, created_at
question        id, round_id, source_id, seq, type(short|multiple), text, explanation
choice          id, question_id, seq, text, is_answer
short_answer    id, question_id, seq, text                   -- 정답 + 유의어
generation_log  id, exam_id, source_id, model, request_summary, response_json,
                duration_ms, error, created_at
participant     id, round_id, nickname, created_at
solo_attempt    id, round_id, participant_id, started_at, submitted_at,
                submit_kind(MANUAL|TIMEOUT|LINK_CLOSED|GROUP_STARTED), correct_count, question_count
solo_answer     id, attempt_id, question_id, choice_ids(json), text
group_room      id, round_id, leader_participant_id, started_at, submitted_at,
                submit_kind(MANUAL|TIMEOUT|LINK_CLOSED), correct_count, question_count
room_member     id, room_id, participant_id, member_no, joined_at, last_seen_at
group_answer    id, room_id, question_id, choice_ids(json), text
generation_log  id, round_id, source_id, model, request_summary, response_json, duration_ms, error
admin / admin_session / setting
```

- **자료와 문제는 차시에 속한다**(스냅샷). 수정으로 새 차시가 생기면 자료·문제를 새 차시로 복사한 뒤 고친다. 이전 차시 결과가 흔들리지 않는다.
- 정답률·선택 비율·대기 인원은 저장하지 않고 조회 시 계산한다(가이드 1-1-1).
- 점수는 `correct_count / question_count`를 제출 시점에 저장하고 %는 계산한다(가이드 1-1-2, 2-4-2).
- `participant`는 차시에 속한다. 같은 폰이 다른 차시에 들어오면 새 응시자다.
- `choice_ids`는 JSON 배열. 가이드 2-2 조건(검색·조인 안 함)에 해당.
- `access_link.token`은 32자 랜덤 URL-safe 문자열, 유일 인덱스.

- 다크 모드.
